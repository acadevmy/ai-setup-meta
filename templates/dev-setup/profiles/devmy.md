# Profile — Devmy workspace

A workspace generated by the Devmy CLI: an Nx + pnpm monorepo from
`scaffold-brick`, with applications and libraries added by other bricks
(`next-application`, `cypress-application`, `nestjs-application`,
`angular-application`, `typescript_library`, …) and addons (`scaffold-gitlab`,
`vercel`).

The setup does not configure the Devmy tooling: it adapts its own files to it.
This profile is the list of what the scaffold does and where the setup handles
it. Each row points to the step that acts; the step's reference holds the
instructions.

## How the bricks behave

- Each brick is rendered from git HEAD, with no pinned version, and
  **overwrites** the files it writes. There is no update mode and no manifest.
- After every brick the CLI runs `pnpm i`, `git add .` and a commit. A brick
  added **after** the setup can overwrite root files the setup adapted, and its
  `git add .` sweeps any uncommitted setup file into its own commit.

So: generate the bricks first, commit the setup on its own, and run the setup
again (UPDATE) after adding a brick.

## What the setup handles

| Devmy behaviour | Effect without the setup's handling | Step |
|---|---|---|
| Next.js app built by Turbopack | `next build` fails in the sandbox (local port) | 3.4b — `allowLocalBinding` |
| Nx daemon and plugin workers | sockets under `/tmp/.nx` denied | 3.4b — Nx sockets |
| `pnpm install` writes `pnpm-lock.yaml` | install and `pnpm add` fail in the sandbox | 3.4b — lock file writable, `Edit()` deny kept |
| husky runs `corepack pnpm` | Corepack cache not writable | 3.4b — Corepack cache |
| `next/font/google` in the Next brick | clean builds fail on the fonts download | 3.4 — font domains |
| `postinstall: dotenv-vault pull`, `devEngines` Node download, Cypress `postinstall` | installs fail in the sandbox | 3.4 — vault, Node, Cypress domains |
| `.env.me` is the vault identity | a worktree cannot pull `.env` | 3.7 — `.worktreeinclude` |
| `.gitignore` has `.env*` | the root `.env.example` is never committed | Step 7 — `!.env.example` |
| `.env` is pulled from the vault on every install | a value typed into `.env` is lost | Step 7 — "add it to the vault" |
| Web tests run in Chromium (Vitest browser + Storybook, Cypress) | on macOS no browser starts in the sandbox | 3b.5 — test command in `excludedCommands`, asked |
| No brick defines a `typecheck` target; `tsc` runs inside `lint` | `nx run-many -t typecheck` is green and checks nothing | 3b.3 — check the target exists |
| Every brick defines `test:headless` | `ng test` may never exit | 3b.3 — prefer `test:headless` |
| GitLab addon: Maintainer-only protection on `main`, `next`, `next-major`, `*.x` | Step 7b would loosen it | 7b.1b — keep an existing protection |
| GitLab addon MR template `merge_request_template.md` | two templates, `vcs-ops` fills the plugin's | 3.8 — any template counts |
| Angular brick `AGENTS.md` without markers | its guide overwritten or the plugin's sections skipped | Step 5 — keep it, append below |

## Better fixed in the bricks

Not the setup's to change; listed so the team can take them to the bricks:

- a `typecheck` script in every brick, with `tsc` out of `lint`, and
  `typecheck` in `requiredScripts`; a `test` script in the Cypress brick;
- `!.env.example` in the scaffold `.gitignore`;
- lint-staged in the husky `pre-commit`, instead of a workspace-wide
  `lint:fix` followed by `git update-index --again`, which re-stages auto-fixes
  silently;
- `test` not depending on `build` in `nx.json`;
- local fonts (`next/font/local`) so a build works offline;
- the CLI's commit messages without literal quotes, and its exit codes checked.
