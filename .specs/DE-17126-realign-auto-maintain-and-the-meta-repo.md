## Context

The prompt audit of 2026-10-06 on `next` found the `auto-maintain` pipeline
still cutting its branch from `main` and opening its PR with `--base main`,
while `AGENTS.md` § Branching makes `next` the base and forbids PRs against
`main` — every run of the pipeline breaks the rule and triggers a release-please
computation nobody decided on. The same audit found the meta-repo's own tooling
(the `clickup` agent, the pre-PR checklist, `validate-template`, the `validate`
skill) stating facts the repository contradicts. This task removes both kinds of
drift. It touches the meta-repo only: nothing under `templates/` or `dist/`.

## Requirements

- REQ-1: Step 3 of `pipeline.md` cuts the branch from `origin/next`, fetched
  explicitly, whatever branch the clone sits on (`git fetch origin next`, then
  `git checkout -b <branch> origin/next`); no command in that step targets `main`.
- REQ-2: Step 8 of `pipeline.md` opens the PR with `--base next`.
- REQ-3: `AGENTS.md` § Flow step 3 says the branch is created from an up-to-date
  `next`.
- REQ-4: `security.md` forbids working directly on `main` **or** `next`.
- REQ-5: In step 6 of `pipeline.md`, `build-plugin.sh` runs **before**
  `next_step` is set to 7, so a run interrupted between the two rebuilds `dist/`
  on resume.
- REQ-6: The `mcp-update` row of the step 4 table points at
  `templates/<dom>/setup/reference/mcp-env.md`, not at a non-existent
  `templates/<dom>/.mcp.json`.
- REQ-7: `.claude/agents/clickup.md` is deleted, and no file of the meta-repo
  (outside `docs/legacy/`, `.specs/` and the CHANGELOG) cites it: the `AGENTS.md`
  tree comment, the "Available agents" table row, and the pipeline "Components"
  list.
- REQ-8: The launchd runner is no longer mentioned in `auto-maintain/SKILL.md`
  (the "was removed" paragraph) nor in `AGENTS.md` (setup step "4. Unload
  launchd"). `docs/migration-v2-to-v3.md` keeps its row.
- REQ-9: The pre-PR checklist item "The template's `CHANGELOG.md` is up to date"
  is replaced by one asking for release-note-ready commit subjects, since
  release-please generates the CHANGELOG.
- REQ-10: `validate-template.md` check 4 requires `.env.*.local`, the pattern
  the template's `.gitignore` actually carries.
- REQ-11: `validate/SKILL.md` no longer says the baseline "shrinks with the PRs
  of the chain": it states the baseline is empty and a new finding gets fixed,
  not baselined.
- REQ-12: The `AGENTS.md` repository tree root reads `ai-setup-meta/`.
- REQ-13: `security.md`'s `.env` rule aligns with `AGENTS.md`: reading is
  allowed when a task needs a value for a real call, a value read never lands in
  a tracked file, a command line or any output, and writes stay denied. The
  false "denied by the settings / the sandbox" rationale for reads is gone.
- REQ-14: `bash scripts/validate-plugin.sh --fail-on-stale` stays green.

## Technical decisions

- **Fetch `next`, cut the task branch straight from `origin/next`** rather
  than `pull --ff-only`: it works identically on a cloud clone of `main` (the
  default branch, `origin/HEAD`) and on a local checkout sitting anywhere, never
  merges, and leaves no local `next` behind.
- **Build first, marker last** — the marker records a completed step, so it
  moves after the build; the build also moves before `/project:validate`,
  which reads `dist/`. Step 6's skip condition is unchanged.
- **Delete, don't realign, the meta `clickup` agent**: the pipeline calls the
  `mcp__clickup__*` tools directly (`security.md` § Operating principles), and
  nothing invokes the agent or its tag intents. `shared/agents/clickup.md` stays —
  it is what the templates distribute.
- **Scope of the rename is the tree root only.** The Routine name
  `auto-maintain ai-base-setup` is live configuration on claude.ai, and the
  `*Generated by: ai-base-setup*` footers ship to projects through `templates/`;
  both stay as they are (decided in discovery).
- **`.env` follows `AGENTS.md`** (decided in discovery): one rule across the
  repo, stated once with its limits, instead of a stricter rule justified by a
  setting that no longer exists.
- `AGENTS.md` version bumped to 2.28.0.
